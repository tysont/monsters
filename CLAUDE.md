# Monster Lane Wars (Roblox game, repo `monsters`)

The implementation plan is `docs/MONSTERS_IMPLEMENTATION_PLAN.md`. Work through it one phase at a
time; tick tasks and record decisions and surprises under each phase's Implementation notes.

## How this project works

- **Code lives in `src/` as `.luau` files.** This repo is the source of truth for all scripts.
- **Rojo** syncs `src/` into the open Roblox Studio place live. On this machine `rojo serve` runs
  from the "Rojo - monsters" scheduled task, so don't start it yourself; the Studio plugin must
  be connected (Plugins tab → Rojo → Connect).
- **Roblox Studio MCP** (`Roblox_Studio` server) is for things that need Studio itself:
  playtesting, console output, screenshots, inspecting the Explorer tree, inserting assets,
  building/editing parts, models, terrain and UI.
- Non-script content (final map art, models, UI layouts, terrain) lives in the cloud place in
  Studio, not in this repo. Exception: the greybox map is generated by code at runtime from
  `MapLayout` (Phase 1), so it lives in the repo; final art (Phase 13) is built in Studio on the
  same layout positions.
- **One place only.** Development happens in the main place; there is no test place until
  Phase 15. Dev-only tools (combat gym, monster authoring, component gallery) are dev-only areas
  or screens inside the main place, never separate places.

## Rules

- **Edit scripts only by editing files in `src/`.** Never change script source through MCP
  (`multi_edit`, setting `.Source` via `execute_luau`, etc.). Rojo overwrites Studio-side
  script edits, so they would be lost.
- MCP `execute_luau` is fine for reading state, building/placing instances, and debugging.
- Before Roblox-specific work, check the MCP `skill` tool for current API guidance.
- After editing code, run `make check` (format check, Selene lint, luau-lsp strict type check,
  Lune unit tests). Use `make fix` to auto-format. Fix all errors before handing off.
- Use `--!strict` at the top of every file in `src/` and `tests/` and type function signatures.
  Lune tooling scripts in `scripts/` use `--!nocheck` (they are not type checked).
- Do not commit or push unless asked.

## Code conventions

- **Requires:** within one container (`src/server`, `src/client`, `src/shared`) use string
  requires: `require("./Sibling")`, and `require("@self/Child")` from an `init.luau`. Across
  containers use instance paths: `require(ReplicatedStorage.Shared.Config)`.
- **Services and controllers:** one ModuleScript each in `src/server/Services/` or
  `src/client/Controllers/`, returning `{ name, dependencies?, init?, start? }`. `init` must not
  yield; `start` runs in its own thread. Started by `Shared.Loader`.
- **Remotes:** define every remote in `src/shared/Remotes.luau` and use it through `Shared.Net`.
  Every client-to-server remote has a `Guard` check; never use RemoteEvents directly.
- **Config:** tunable numbers go in `src/shared/Config`, read with `Config.get()`.
- **Tests:** `tests/**/*.spec.luau`, run under Lune. Keep logic you want tested in shared modules
  that don't touch the engine when required, and inject `task`/clock/engine dependencies.

## File → Studio mapping (see `default.project.json`)

| Folder           | Studio location                                   |
|------------------|---------------------------------------------------|
| `src/server`     | `ServerScriptService.Server`                      |
| `src/client`     | `StarterPlayer.StarterPlayerScripts.Client`       |
| `src/shared`     | `ReplicatedStorage.Shared`                        |
| `Packages`       | `ReplicatedStorage.Packages` (Wally, when present) |
| `ServerPackages` | `ServerScriptService.ServerPackages` (Wally)      |

Naming: `Foo.server.luau` → Script, `Foo.client.luau` → LocalScript, `Foo.luau` → ModuleScript.
A folder with `init.luau` becomes a ModuleScript whose children are the folder's other files.

## Tooling

Tools are pinned in `rokit.toml` (Rojo, StyLua, luau-lsp, Selene, Wally, Lune). Targets are in the
`Makefile`: `setup`, `check`, `fix`, `lint`, `typecheck`, `test` (`FILTER=...`), `build`,
`packages`, `serve`. Make recipes are single commands so they work from PowerShell (no `sh`);
put anything more complex in a Lune script under `scripts/`.
